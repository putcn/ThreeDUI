# Spike ③：`@pmndrs/glyph`（MSDF）vs `SystemFontEngine`，中文文字（可抛弃）

代码：`spikes/glyph-cjk/`（`pnpm spike:glyph`，端口 5175）。左列 = `@pmndrs/glyph@0.1.0` MSDF，右列 = `@glassui/text` 的
`SystemFontEngine`（Canvas2D → 图集页 → `CanvasTexture`，每个图集页合并成一个 quad 网格）。两列在同一平面、同一
`WebGPURenderer` 下，同一字符串 `创建你的账号 Create your account 14天免费试用 ①②③ — 「引号」…`，字号 14 / 17 / 24 / 46 pt，
外加一行探针 `probe: 鬱龘 (not in subset)`（这两个字不在打包的字体子集里）。

- 参数：`?webgl` 强制 WebGL2 后端；`?baked` 改用离线烘焙的 `.font.glb`；`?full` 改用完整 Noto Sans SC（10.5 MB）运行时烘焙；
  `?os=N` 改 `SystemFontEngine` 的 oversample；`?pingfang` 让右列用系统 PingFang SC。`?baked` / `?full` 读取
  `spikes/glyph-cjk/local/`（gitignore；见文末"复现"）。
- 字体：Noto Sans SC Regular（OFL，许可证见 `fonts/OFL.txt`；Google Fonts 静态 TTF），用 `pyftsubset` 裁成 ASCII + 测试串
  （22 KB / 144 字形，`fonts/NotoSansSC-spike.ttf`）。
  glyph 的 README 提供 CLI 烘焙器（`glyph bake`），所以按 brief 打包子集。为了在**同一字形轮廓**上比清晰度，右列也通过 CSS
  `FontFace` 用这份子集绘制；子集之外的字由 Canvas2D 按字回退到系统字体（PingFang SC 等）。
- 相机：起始距离使 1 pt ≈ 1 CSS px（DPR 2）；`__spike.view('zoom3glyph' | 'zoom3system' | 'angle60' | 'front')` 给出截图用的
  机位（3× 推近、绕 X 轴倾斜 60°，两列与相机等距）；也可拖拽环绕。
- 环境：Chrome（MCP 自动化标签页，`document.visibilityState === 'hidden'`），M 系列 Mac，DPR 2，1512×808。

## 测量

| 项 | `@pmndrs/glyph` 0.1.0（MSDF） | `SystemFontEngine`（Canvas2D 图集） |
|---|---|---|
| **(a) 字符是否全部渲染** | 测试串 4 行全部渲染（每行 46 个字形，`measure().missingGlyphCount = 0`）。探针行 `鬱龘` → `.notdef`，**空白**（`missingGlyphCount = 2`），无回退：`createFontStack` 只能回退到其它**已加载并烘焙**的 glyph 字体，不能回退到系统字体。 | 全部渲染：177 个字形 quad 逐个读回图集像素，无空白字形。探针 `鬱龘` 由 Canvas2D 回退到 PingFang SC 正常显示。 |
| **(b) 清晰度 1×** | 清晰，与右列同一轮廓下肉眼无差别。 | 清晰（oversample 2 × DPR 2 正好 1:1 纹素）。 |
| **(b) 清晰度 3× 推近** | 14–24 pt：边缘锐利，明显好于右列。**46 pt：MSDF 伪影**——"建 的 账 号 C" 的笔画拐角/交叉处出现缺口和毛刺（默认 em-size 64、pixel range 8 对复杂汉字在大屏幕尺寸下不够）。WebGL2 下伪影完全相同（是烘焙数据的问题，不是后端）。 | 14–24 pt：位图被放大 3×，**明显发软**。46 pt：边缘软但干净，无伪影。 |
| **(b) 60° 倾斜** | 14/17 pt 行的细笔画变淡、断续（MSDF 在掠射角下按屏幕导数收缩）；大字号正常。 | 略糊但更"实"、可读（mipmap + 8× 各向异性）。 |
| **(c) 首帧时间**（自导航起） | 运行时烘焙（dev，22 KB 子集）：字体加载+烘焙 **1.9–2.0 s**（2 次，推测标签页刚被截图激活；与 Node CLI 的 2.2 s 栅格耗时一致）/ **9.7–22 s**（其余 12 次，后台标签页）；首次绘制 = 烘焙完成后 +0.3–1.3 s。预烘焙 `.font.glb`（prod）：字体加载 53–423 ms，首次绘制 **0.67–1.16 s**（后台标签页每秒约 1 帧，是上限）。Node CLI 烘焙同一子集：栅格 2.2 s，总 5.1 s。 | 首帧 **95–330 ms**（含 `renderer.init()`）；布局+栅格化 15–43 ms（dev）/ 112–143 ms（prod，与 glyph 模块并行加载争主线程）；子集 `FontFace` 加载 5–14 ms（用系统字体时为 0）。 |
| **(c) 下载字节**（prod 构建） | JS ≈ 571 KB（≈ 143 KB gzip，不含 three）；`text-shaper.wasm` 1.36 MB（497 KB gzip，必下）；每个字体 `.font.glb`：**2.62 MB**（525 KB gzip / 349 KB brotli）——仅 144 个字形（114 个码位：ASCII + 测试串）。运行时烘焙另需 `font-baker.wasm` 1.07 MB + `mtsdf-baker.wasm` 0.55 MB + worker。 | JS 8.6 KB（3.3 KB gzip）；字体 0 字节（系统字体）。本 spike 为同轮廓对比额外加载 22 KB 子集。 |
| **(c) GPU 内存** | MSDF 页 1022×638 RGBA = 2.6 MB / 144 字形（≈ 18 KB/字形，em 64）。 | 1 张 2048² RGBA 图集页 = 16.8 MB（含 mip ≈ 22 MB），实际只用了一小块。 |
| **(d) draw calls**（`renderer.info.render.drawCalls`，已减去空场景也有的 1 次输出 pass） | **2**（5 段文字共用 1 个 `InstancedBufferGeometry` 网格，挂在 glyph 自己的根 `Object3D` 下，不在调用方的 Group 里），700 三角形。WebGPU / WebGL2 相同。 | **1**（每个图集页 1 个合并网格），354 三角形（177 quad）。WebGPU / WebGL2 相同。整帧：平面 1 + 两列 3 + 输出 pass 1 = 5。 |
| **(e) 按需生成 vs 预制字符集** | **需要预制字符集**。MSDF 栅格在字体加载时按整个 cmap（或声明的 `coverage: { text / unicodeRanges / glyphIds }`）一次烘焙，之后不能按字追加；覆盖外的字是 `.notdef`（或 `RasterCoverageError`）。README 也写明 CJK "Large-coverage paging … future work"。完整 Noto Sans SC（30 796 字形）离线烘焙 **10 分 50 秒未完成**（已中止）；GB2312 一级字（4 199 字形）烘焙 4 分钟、产物 81.6 MB（见下）。运行时烘焙（`.ttf` 源）只在 dev 可用：**Vite 8 生产构建里 `runtime-bake-worker.js` 被当作原样资源拷贝，其相对 import 不存在 → `Error: Worker failed`**，生产环境只能用 CLI 预烘焙 `.font.glb`。 | **按需**：每个（字体, 字素簇）在首次 `layout` 时栅格化进共享图集，LRU 换页；任何系统能画的字都可用，无需字符集。 |
| **(f) WebGL2 后端一致性** | ✅ `WebGPURenderer({ forceWebGL: true })` 下渲染、draw calls（2）、伪影都与 WebGPU 相同（README 只排除经典 `WebGLRenderer`）。 | ✅ 完全一致，draw calls 1。 |


### 其它发现
- npm 包（0.1.0）**不带 README**，API 只能看 GitHub README 与 `src/`。`layout.align` 只接受 `start | center | end | justify`（`'left'` 抛 `TypeError`）。
- `glyph.fontFace('x.ttf')` 会先探测同名 `x.font.glb`；Vite dev 对不存在的路径返回 `index.html`（200），glyph 把它当作"无效的烘焙资源"静默忽略后转运行时烘焙——能用，但每次多一次请求。
- 换行：glyph 遵守避头尾（不把「」…放到行首），但**没有标点悬挂**：17 pt 行宽 534.2 pt > 520，于是把"号」…"整体折到下一行；我们的引擎让末尾"…"悬挂，保持一行（536.4 pt）。行宽两者相差 0.4%（harfrust 整形 vs Canvas `measureText`）。
- glyph 的文字不挂在调用方的 `Group` 下（隐藏 Group 不会隐藏文字）；它自己维护一个根 `Object3D` 与提交状态（`commitState()`：`pending → committed`），**只在帧更新时提交**——后台标签页（无 rAF）里永远不会出字，spike 里改用定时器驱动渲染循环。
- 后台标签页对 glyph 运行时烘焙影响极大（同一 22 KB 子集 2 s ↔ 22 s），系统字体路径不受影响。

## 决定

**默认 SystemFontEngine，glyph 后置**

依据 brief 的判定规则：glyph 对子集外的中文字符直接空白（a），并且**需要预制字符集**（e：MSDF 按字体/覆盖范围一次性烘焙，
不能按字生成；生产构建中运行时烘焙不可用；全量中文字体烘焙在分钟级、产物上百 MB 量级）。WebGL2 一致（f）不构成阻碍，
3× 推近小字更锐利（b）是它唯一的明确优势，但大字号汉字有 MSDF 伪影。GlassUI 的输入框、用户内容必须能显示任意中文，
所以默认引擎必须是按需的系统字体路径；glyph 只适合"字符集已知、可离线烘焙"的场合（品牌/展示用拉丁字体、图标字体）。

## Plan 2 后续任务

1. **Plan 2 Task: `SystemFontEngine` 的 three.js 文字渲染器**（`@glassui/three` 内）——每个图集页一个 `CanvasTexture`，
   按（文字批次, 图集页）合并 quad 几何（本 spike 右列即参考实现：1 draw/页），每帧上传 `atlas.dirtyPages` 后
   `clearDirty()`；`MeshBasicNodeMaterial` 以图集 alpha 为遮罩、样式颜色着色；mipmap + 各向异性（60° 下可读性来自这里）。
2. **Plan 2 Task: 随缩放重栅格化（raster LOD）**——按文字节点的屏幕尺度（每 pt 对应的设备像素，由相机与世界矩阵算出）
   选择 oversample 档位 {1, 2, 4, 8}（带迟滞），档位进入图集 key，旧档位交给 LRU 淘汰。验收：14 pt 文字在 3× 推近下与 1×
   一样锐利（本 spike 中 oversample 2 在 3× 下明显发软）。若重栅格化抖动过大，备选方案是在 `AtlasManager` 中从 Canvas2D
   栅格生成单通道 SDF（TinySDF 式，仍按需）。
3. **Plan 2 Task: 图集内存**——图集页改单通道（R8/alpha）纹理、默认 `pageSize` 降到 1024：本 spike 177 个字形占了一整张
   2048² RGBA 页（16.8 MB，含 mip ≈ 22 MB）。
4. **Plan 2 Task: `TextEngine` 契约测试套件**——把 measure / layout / caret / selection 的行为测试做成可对任意实现运行的
   套件（含避头尾与标点悬挂、空白字形像素检查），为将来接入第二个引擎留口子，core 不感知具体引擎。
5. **后置（Plan 2 之后，可选）: `MsdfEngine` 适配器**——基于 `@pmndrs/glyph` 的**预烘焙** `.font.glb`，只用于已知字符集的
   拉丁/品牌/图标字体（大标题、展示字），逐字回退到 `SystemFontEngine`（依据 `.notdef` / `missingGlyphCount`）。重新评估
   的前提：glyph 发布 CJK 大字符集分页（README 的 future work）或按需生成、Vite 生产构建下运行时烘焙可用、大字号伪影解决
   （先试 `--msdf em-size=128`，代价是 GPU 内存 ×4）。

## 复现
```bash
pnpm install && pnpm spike:glyph                    # http://localhost:5175/ ，?webgl 切 WebGL2
# 可选：?full / ?baked 需要的本地文件（不入库）
curl -A "Mozilla/4.0" "https://fonts.googleapis.com/css2?family=Noto+Sans+SC:wght@400"   # 取 TTF 地址，下载为 spikes/glyph-cjk/local/NotoSansSC-Regular.ttf
spikes/glyph-cjk/node_modules/.bin/glyph bake --input spikes/glyph-cjk/fonts/NotoSansSC-spike.ttf \
  --output spikes/glyph-cjk/local/NotoSansSC-spike.font.glb --msdf
```
控制台：`__spike`（计时）、`__spike.measure()`（各列 draw calls / 三角形）、`__spike.bytes()`（资源字节）、`__spike.view(name)`。
